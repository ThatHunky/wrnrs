# Модуль «Гра»: правда або дія

**Дата:** 2026-08-30
**Статус:** спроєктовано, чекає на план
**Обсяг:** модуль №3 суперапу — картки «правда» і «дія» з чергуванням імен

---

## 1. Контекст

`WRNRS / між нами.` — живий Telegram-бот для пар. На момент цього спека вже є:

- **каркас модулів** (`internal/catalog`, `internal/modules`) — фасетні каталоги, детермінований вибір без повторів, гейт доступу, реєстр із диспетчеризацією за префіксом колбека;
- **модуль поз** — 519 позицій, картинки в MinIO, фільтри, спільні відмітки, крутилка;
- **модуль бажань** — 60 бажань, приватні відповіді, збіги, звʼязок із рандомайзером поз;
- гра в картки, паринг, теми, Telegram Stars, адмінка.

Цей модуль — етап 3 карти суперапу («кубики дій» + «фанти»).

---

## 2. Що виявилось при проєктуванні

Карта суперапу перелічувала кубики й фанти окремо. **Це одне й те саме.** Фант — це правда або дія; кубик дій — це та сама дія. Два модулі означали б двічі написаний однаковий код і дві кнопки в меню замість однієї.

Друге: «кубики» можна було зробити справжнім множенням «дієслово × ціль», отримавши сотні комбінацій із кількох десятків слів. Українською це ламається на відмінках — «Поцілуй **шию**», але «Торкнись **шиї**», бо відмінок визначає дієслово. Наївний перебір видавав би покручене, а відмінкова таблиця — це окремий движок заради економії на письмі. Тому картки пишуться цілком.

## 5. Стан партії

Живе в Redis під ключем модуля (`SetModuleState`/`ModuleState`, `mod:play:user:{id}`), як `BrowseState` у позах. Структура:

```go
type GameState struct {
    Filter catalog.Filter `json:"f"`
    // Draw counts every card drawn. Folded into the shuffle bucket so two
    // consecutive taps never replay the same deterministic shuffle — the
    // exact bug that shipped in the positions randomiser and had to be fixed.
    Draw int `json:"d"`
    // Recent holds the last N card ids so the same card does not come back
    // immediately. Bounded; this is a play-session ring, not history.
    Recent []string `json:"r"`
    // TurnB is true when the next card addresses partner B rather than A.
    TurnB bool `json:"t"`
}
```

Redis може бути недоступний (бот падає на старті без нього, тож це досяжно лише якщо Redis помер посеред партії). Тоді стан не зберігається, і деградація виглядає так:

- черга не рухається: `TurnB` завжди `false`, кожна картка називає перше імʼя;
- кільця «без повторів» немає: `Recent` завжди порожнє, картка може повторитись одразу;
- `Draw` не зростає, тому детермінований шафл сам по собі видавав би **ту саму картку на кожен тап** — і Telegram відхиляв би незмінний `editMessageText`, а `presentText` слав би нове повідомлення на кожен дотик. Щоб цього не сталося, хендлер при невдалому збереженні перетягує картку ще раз, домішуючи в бакет `nonce` з годинника (`Service` лишається без I/O — `nonce` приходить параметром у `Next`).

Модуль лишається робочим — це свідома деградація, як і всюди в цьому боті.

`Recent` обмежене 15 елементами. Більше не має сенсу: кільце існує, щоб картка не повторилась одразу, а не щоб замінити no-repeat, який дає `SelectNext`.

## 6. Чергування імен

Бот бере відображувані імена обох партнерів (`UserDisplayName`) і підставляє перед текстом картки: `Оля: поцілуй партнера в шию`.

- З парою: імена чергуються за `TurnB`, який перемикається після кожної виданої картки.
- Без пари: імені немає, картка показує лише текст.
- Якщо імʼя партнера порожнє, використовується локалізований запасний варіант — той самий `menu.partner_fallback`, який уже є в каталозі рядків.

Чергування **не** намагається бути справедливим після пропусків: пропущена картка не змінює чергу. Інакше пропуск ставав би способом перекинути дію на партнера.

## 7. Екрани

Префікс колбеків: `play:`

### Хаб `play:open`
Коротке пояснення, кнопка `▶ Далі`, кнопка `☰ Фільтри`, повернення в меню. Якщо пари немає — рядок про те, що з парою картки звертатимуться на імена.

### Картка `play:next`
Підпис: імʼя (коли є пара), тип картки (правда / дія), текст, рівень інтенсивності. Кнопки: `▶ Далі` · `⏭ Пропустити` · `☰ Фільтри` · `⌂ Меню`.

`Далі` й `Пропустити` роблять одне й те саме — беруть наступну картку. Різниця лише в тому, що `Пропустити` не перемикає чергу (див. розділ 6). Обидві кнопки присутні, бо вони означають різні наміри для того, хто грає.

### Фільтри `play:filters` / `play:filter:{facet}:{value}`
Перемикачі за `kind` (правда / дія) і `intensity`. Це рівно `catalog.Filter`, без нового коду. Якщо вибірка порожня — окреме повідомлення з підказкою послабити фільтри, а не мовчазний порожній екран.

## 8. Контент

`content/play.v1.json` у форматі `internal/catalog`: рівно 80 елементів, обидві мови обовʼязкові.

Фасети:
- `kind` — `truth` або `dare`, рівно 40 кожного
- `intensity` — `gentle`, `medium`, `bold`

ID — `p001`…`p080`, **нуль-доповнені**: `catalog.Filtered` сортує лексикографічно.

Правила тексту:
- `title` не використовується як заголовок картки — картка показує `body`. Але `title` обовʼязковий для `Validate` і слугує коротким ярликом у логах і фільтрах; тримати до 40 символів.
- `body` — одне речення, 30–160 символів, у наказовому способі для `dare` («Поцілуй…») і питальному для `truth` («Що…?»).
- Дія має бути виконуваною тут і зараз, без реквізиту, якого може не бути вдома.
- **Нічого, що потребує третьої особи або згоди поза парою.** Та сама межа, що в каталозі бажань.
- Кожна мова пишеться природно, а не як переклад іншої.

Розподіл інтенсивності — точний, щоб тест міг його перевірити: 30 `gentle`, 30 `medium`, 20 `bold`. У межах кожного `kind` розподіл однаковий: 15 / 15 / 10.

## 10. Що НЕ входить

- очки, стріки, статистика;
- синхронізація між двома телефонами;
- звʼязок із вішлістом (фільтр «тільки збіги») — картки не входять у каталог бажань;
- власні картки від користувачів;
- монетизація.

## 11. План тестування

- Чергування: після виданої картки черга перемикається; після пропущеної — ні.
- Без пари: імені на картці немає, модуль працює.
- Порожнє імʼя партнера дає локалізований запасний варіант, а не порожній префікс.
- Кільце нещодавніх: та сама картка не повертається одразу; кільце обмежене 15.
- `Draw` інкрементується щоразу, і два послідовних натискання дають різні картки.
- Фільтр за `kind` і за `intensity`; порожня вибірка дає пояснення, а не порожній екран.
- Стан переживає `EncodeState`/`DecodeState` цілком, включно з `Recent` і `TurnB`.
- Redis відсутній: модуль не падає, деградує передбачувано.
- Груповий чат відхиляється.
- Каталог: 80 елементів, 40/40 за `kind`, ID нуль-доповнені й відсортовані, обидві мови.
- i18n: набори ключів обох мов симетричні.

## 12. Ризики

**Контент вигорає.** 80 карток — це кілька вечорів. Мітигація: no-repeat робить перші проходи свіжими, а дописати картки — це правка JSON без коду. Якщо модулем користуватимуться, розширення дешеве.

**Картка може не пасувати моменту.** Не кожна дія доречна будь-коли. Мітигація: фільтр за інтенсивністю й кнопка пропуску без наслідків.

**Чергування дратуватиме, якщо здаватиметься несправедливим.** Мітигація: правило просте й передбачуване — видана картка перемикає чергу, пропущена ні. Воно назване в інтерфейсі одним рядком, щоб не здавалося випадковим.
