# Суперапп для пар: каркас модулів + рандомізатор поз

**Дата:** 2026-08-29
**Статус:** спроєктовано, чекає на реалізацію
**Обсяг:** карта модулів усього суперапу + детальний дизайн Модуля 0 (каркас) і Модуля 1 (рандомізатор поз)

---

## 1. Контекст

`WRNRS / між нами.` — Go-бекенд Telegram-бота для синхронізованої карткової гри для пар. Наявний стан:

- парна гра з колодою 32 питання на 3 рівні (`internal/game`, `content/questions.v1.json`);
- детермінований вибір карт без повторів із сідом по `pair_id + level + cycle` (`internal/content/deck.go`);
- рендер карток-зображень з темами, шрифтами, фонами (`internal/render`);
- гейтинг 18+ і mature-контенту: картка з `requires_mature_opt_in` показується лише коли **обидва** партнери підтвердили 18+ і окремо увімкнули mature;
- журнал відповідей, власні питання, Telegram Stars, адмін-гранти;
- SQLite (durable) + Redis (FSM, локи, рейт-ліміти) + MinIO (оброблені WebP).

Мета цього спека — перетворити бота на «суперапп» для пар, не зламавши наявну гру.

## 3. Карта модулів

### Спільна інфраструктура

- **`internal/catalog`** — узагальнений движок каталогів (див. розділ 4).
- **`internal/scheduler`** — зараз **не існує**. Потрібен для дейлі, нагадувань і річниць. Вводиться на етапі 4.
- **`internal/assets`** — шар медіа-асетів модулів поверх наявного `objectstore`.

### Модулі

**На движку каталогів** (після каркасу кожен коштує день-два):

1. Рандомізатор поз *(mature)* — модуль №1
2. Кубики дій *(mature)*
3. Фанти / правда-дія *(safe + mature набори)*
4. Ідеї побачень *(safe)*

**З власною механікою:**

5. Вішліст бажань з матчингом *(mature)* — приватні відповіді обох, показуються лише збіги
6. Питання дня + streak *(safe)* — потребує шедулера
7. Чек-ін настрою *(safe)*
8. Компліменти карткою *(safe)*
9. Календар і річниці *(safe)* — потребує шедулера
10. Спільні списки й цілі *(safe)*

**Надбудова:**

11. Профіль пари, ачівки, статистика

### Порядок

| Етап | Що | Обґрунтування |
|---|---|---|
| 1 | Каркас (М0) + рандомізатор поз (М1) | пріоритет власника; каркас окупається вже на другому модулі |
| 2 | Вішліст з матчингом (М5) | найсильніша механіка для пари; підсилює М1 — рандомайзер починає крутити лише те, на що обидва погодились |
| 3 | Кубики + фанти (М2, М3) | майже безкоштовно на готовому движку |
| 4 | Шедулер + дейлі + чек-ін (М6, М7) | шедулер — окрема інфраструктура, тому не раніше |
| 5 | Побачення, компліменти, календар, списки (М4, М8, М9, М10) | добірка на готовому |
| 6 | Гейміфікація (М11) | має сенс лише коли є що рахувати |

## 4. Модуль 0 — каркас

### 4.1 `internal/catalog`

Узагальнення того, що вже працює в `internal/content/deck.go`.

```go
type Item struct {
    ID     string
    Facets map[string][]string   // "level" -> ["easy"], "location" -> ["bed","sofa"]
    Text   map[string]ItemText   // lang -> {Title, Body}
    Media  *MediaRef             // optional
}

type Catalog struct {
    Kind    string   // "positions", "dares", "dates", ...
    Version int
    Items   []Item
}

type Filter struct {
    Include map[string][]string  // фасет -> дозволені значення (OR у межах фасета, AND між фасетами)
    Exclude map[string][]string
}
```

Обовʼязки:

- `Validate(languages []string) error` — кожен елемент має текст для кожної мови; дублікати ID заборонені. Дзеркалить `Deck.Validate`.
- `Filtered(f Filter) []Item`.
- `SelectNext(SelectionInput) (Item, cycle int, exhausted bool, err error)` — та сама механіка, що `content.SelectNextCard`: спершу небачені, при вичерпанні `cycle++` і детермінований решафл. На відміну від `content.SelectNextCard`, сід береться з узагальненого `SeedID int64`, а не з `PairID` — це дозволяє тому самому движку обслуговувати і парні, і соло-модулі (див. 5.8).

Наявна колода питань **не мігрує** на цей движок у межах цього спека. `internal/content` лишається як є; `internal/catalog` — паралельна абстракція для нових модулів. Міграцію колоди розглядаємо окремо, коли на движку буде 2-3 модулі й патерн підтвердиться.

### 4.2 Реєстр модулів

```go
type Module struct {
    ID            string   // "positions"
    TitleKey      string   // i18n ключ
    Icon          string
    Gate          Gate     // NeedsPair, Needs18Plus, NeedsMature, NeedsPremium
    CallbackPrefix string  // "pos:"
}
```

Головне меню будується з реєстру. Додати модуль = дописати запис + хендлер, а не правити `MainMenuKeyboardWithPair` і `switch` у `app.go`.

### 4.3 Розвантаження `app.go`

`internal/app/app.go` — **3002 рядки**. Це вже за межею, за якою файл важко тримати в голові й безпечно редагувати. Каркас включає витягування роутингу в per-module хендлери з інтерфейсом:

```go
type Handler interface {
    Prefix() string
    HandleCallback(ctx context.Context, cb *telegram.CallbackQuery) error
    HandleMessage(ctx context.Context, msg *telegram.Message) (handled bool, err error)
}
```

Це не рефактор заради рефактору: без нього М1 нікуди класти. Наявні флоу (онбординг, паринг, гра, тема, адмін, платежі) **не переписуються** — вони лишаються там, де є. Виноситься лише механізм диспетчеризації, щоб нові модулі не росли в `app.go`.

### 5.3 Інжест

Окрема разова тулза `cmd/ingest-positions`, **не частина рантайму бота**.

- обхід `/positions/page/1..11` для збору списку ID, далі кожна сторінка поза;
- тротлінг 1 запит/сек (519 сторінок + 519 зображень ≈ 17 хв);
- `--resume` через файл прогресу, щоб не починати з нуля після обриву;
- **детектор статейних сторінок:** якщо `<h1>` не матчить `Sex position #\d+\. (.+)`, сторінка не парситься автоматично, а йде у `review.json`. Очікується ~18 таких (напр. `#67 Missionary` — стаття про 42 варіації з тегами `easy-level` і `crazy` одночасно);
- на виході: `content/positions.v1.json` (метадані) + зображення у MinIO.

**Зображення не комітяться в git.** Репозиторій — це вже публікація, і чужий контент там лежати не повинен. Бакет і префікс — з конфігу (`POSITIONS_BUCKET`, `POSITIONS_PREFIX`), що й реалізує Р10: підміна джерела = зміна конфігу й перезапуск інжесту.

Зображення зберігаються **байт-у-байт**, без ресайзу й перекодування — це зберігає вотермарки джерела (Р5) і мінімізує роботу.

### 5.4 Переклад

Повний переклад усіх 519 назв і описів українською (Р9). Формат:

```json
{
  "id": "519",
  "facets": {"level": ["medium"], "location": ["sofa"], "type": ["cowgirl"]},
  "media": {"key": "positions/519.png", "width": 500, "height": 384},
  "text": {
    "en": {"title": "Revelation", "body": "..."},
    "uk": {"title": "Одкровення", "body": "..."}
  },
  "tags": ["starter_100"]
}
```

Переклад робиться пакетами й вичитується власником перед мерджем — тема чутлива до формулювань, машинний переклад «як є» не приймається.

### 5.5 `starter_100`

Курована сотня: 18 позицій із секції «Most popular» + 17 із статті на головній (набори перетинаються — дедуплікуємо за ID) + добір до рівно 100 за покриттям фасетів `level` і `location`, щоб не було перекосу в екзотику. Тег `starter_100` у тому ж JSON.

Рандомізатор за замовчуванням крутить `starter_100`; повний каталог відкривається явним перемиканням фільтра.

### 5.6 Сховище

Нова таблиця:

```sql
CREATE TABLE pair_position_marks (
    pair_id        INTEGER NOT NULL REFERENCES pairs(id) ON DELETE CASCADE,
    position_id    TEXT    NOT NULL,
    tried_at       TIMESTAMP,
    favorited_at   TIMESTAMP,
    hidden_at      TIMESTAMP,
    marked_by      INTEGER REFERENCES users(telegram_id) ON DELETE SET NULL,
    updated_at     TIMESTAMP NOT NULL,
    PRIMARY KEY (pair_id, position_id)
);
```

- відмітка спільна для пари (Р8), обидва бачать одну;
- при **видаленні акаунта** зникає каскадом разом з парою;
- при **розриві пари** лишається — рядок `pairs` живе далі зі статусом `ended`, і при поверненні контекст не губиться;
- `hidden_at` — «не показувати нам це», щоб фільтрувати небажане без видалення з каталогу.

Фільтри користувача зберігаються в Redis FSM (`fsm:user:{id}`), бо це транзієнтний стан перегляду, а не durable дані.

### 5.7 Екрани

**Хаб модуля:** `🎲 Крутити` · `📖 Каталог` · `⭐ Улюблені` · `✅ Пробували` · `☰ Фільтри` · атрибуція джерела з посиланням (Р5).

**Браузер** — одне повідомлення з фото, що редагується на місці:

- підпис: назва, фасети, опис;
- кнопки: `◀` `▶`, `✅ Пробували`, `⭐`, `🎲`, `☰`;
- використовує наявний патерн `editMessageCaption` з фолбеком на нове повідомлення, коли старе вже не редагується — він уже працює для карток гри.

**Фільтри** — фасети кнопками-перемикачами, стан у Redis, лічильник «знайдено N».

**Дамп** — `Надіслати всі (N)`:

- підтвердження з кількістю й оцінкою часу;
- тротлінг ~1 повідомлення/сек у межах чату;
- кнопка «стоп», що перериває відправку;
- застосовується до **поточного фільтра**, не до всього каталогу.

### 5.8 Гейтинг

- вхід у модуль: **власні** 18+ і mature-opt-in;
- спільні дії (відмітки, «показати партнеру»): mature-opt-in **обох** партнерів;
- це не змінює наявного правила для парних карток гри, і водночас не блокує людину без пари.

**Поведінка без пари.** Модуль доступний соло: браузер, фільтри й крутилка працюють. Сід рандомізації береться з `pair_id`, коли пара є, і з `telegram_id`, коли її немає — `SelectionInput` приймає узагальнений `SeedID`, а не `PairID`. Недоступні соло лише спільні дії: `✅ Пробували` і `⭐` вимагають активної пари, бо `pair_position_marks` ключується парою. Соло-користувачу ці кнопки показуються неактивними з підказкою «потрібна пара», а не ховаються — інакше незрозуміло, чого бракує.

Рейт-ліміт: наявний механізм `rate:user:{id}:{action}` з новою дією `positions`. Окрема дія для дампу, щоб перегляд і масова відправка не ділили один бакет — помилка, яка вже є в апловуді фонів.

## 7. План тестування

- `internal/catalog`: валідація (відсутня мова, дублікат ID), фільтрація (OR у фасеті, AND між фасетами), no-repeat і `cycle++` при вичерпанні, детермінізм сіду по парі.
- Реєстр модулів: гейт пропускає/блокує за кожною комбінацією (`18+`, `mature`, `пара`, `преміум`).
- Парсер інжесту на збережених фікстурах: `p519.html` → повний коректний запис; `p67.html` → потрапляє в `review.json`, а не в каталог.
- Таксономія: невідомий slug валить інжест із явною помилкою.
- `pair_position_marks`: відмітка одним партнером видима другому; каскад при видаленні акаунта; збереження при розриві пари.
- Дамп: тротлінг витримує інтервал; «стоп» реально перериває; дамп поважає активний фільтр.
- Рейт-ліміт: перегляд і дамп не ділять один бакет.

Власник продукту поінформований і свідомо ухвалив рішення використовувати асети без окремої домовленості з правовласником (Р4). Наслідки, які лишаються можливими: DMCA-скарга, вимога видалення, скарга до Telegram і блокування бота.

Пом'якшення, вбудовані в дизайн:

- вотермарки джерела зберігаються (Р5);
- атрибуція з dofollow-посиланням присутня в екрані модуля (Р5);

**Обсяг перекладу.** 519 назв і описів — найбільша разова робота в модулі. Мітигація: інжест і код не блокуються перекладом; `starter_100` перекладається першим, решта доливається без міграцій.

**Розмір `app.go`.** Якщо каркас (4.3) не зробити до М1, файл піде за 3500 рядків і кожен наступний модуль дорожчатиме. Мітигація: 4.3 входить в етап 1 як обовʼязкова частина, а не «якщо буде час».
